# UI/UX 自查清单（2026-11-02 起）

老板对当轮界面的原话：**「路径规划功能的 UX 和 UI 都是灾难级别的，别的地方也有很多 UI/UX 不对，自查自纠」**。
本文件是自查的**唯一清单**：每条缺陷 → 违反的规则 → 修法 → 证据（截图/测量）→ 状态。
状态只有三个：`OPEN` / `FIXED` / `REJECTED`（写清为什么不做）。

## 0. 适用于全部界面的规则（违反其一即记一条缺陷）

| 代号 | 规则 |
|---|---|
| R1 空白 | 内容短时面板要**贴合内容**；展开面板里出现整块空白即为缺陷 |
| R2 否定噪音 | 不可用的控件不要显示成灰按钮；按需渐显（progressive disclosure） |
| R3 一物一职 | 同一个状态不允许有两个入口（例：`收藏` chip 与 ♡ 并存） |
| R4 可读的入口 | 图标按钮必须能读出含义：有 contentDescription、有统一 48 dp、有分组 |
| R5 角色一致 | 容器/文字/按钮层级全 app 一套（见 `UIUX-REWORK.md` §surface rules） |
| R6 主体可见 | 屏幕上最重要的对象（当前模拟点）必须在任何底图上清晰可辨 |

## 10. 悬浮窗（第六轮）验收：四项全 PASS（2026-11-02 06:45）

根因不是 z-order、也不是"不可点标志"，而是**窗口矩形与画布没对齐**（插入条只应用在一侧）。
修法：`layoutInDisplayCutoutMode = SHORT_EDGES` + `fitInsetsTypes = 0`（API 30+），
**没有**采用 212 px 补偿这种 hack。

|---|---|---|---|
| 1 | 本 app 前台时隐藏 | **PASS**：工具页开关 ON 且无气泡遮挡；`stage=shown → hidden/suspended` 相隔 57 ms | `_overlay-inapp2.png` |

| 4 | 点 ✕ 关闭且开关置 off | **PASS**：`stage=hidden`，回到工具页该行显示 Switch OFF | `_overlay-switch-off.png` |

额外：拖动表盘只移动摇杆把、松手回中，**下层没有任何响应**（`topResumedActivity` 仍是桌面）；
旧的"点穿到 app 里误点收藏"在该场景下已结构性不可能（前台时窗口直接被移除）。

**新缺陷（未修，下一窗口第一优先）**：设置页三个滑块的**拇指渲染是坏的**——`位置更新频率` 的拇指是一个被轨道左缘裁切的粗"C"，三个滑块都出现**与轨道分离的竖条**、数值点在轨道最右端。这不是风格问题，是控件坏了。修法候选：显式 `SliderDefaults.Thumb`(~20 dp) 或给 Slider 显式高度让轨道与拇指共用基线；**并且必须在浅色与深色各拍一次**（固定尺寸常在其中一种主题下裁切）。

**待拍**：设置底部两段式（保存/恢复默认）、规划的**真正空态**（当前"空态"其实是恢复的上次计划）。

| 状态 | 工具胶囊 | 板起点 | 结论 |
|---|---|---|---|
| 720×1280 窄屏 | `[324,133][478,287]` | 522 | **478 < 522，无相交**，图标态，搜索栏从 148 px 长到 258 px |
| 1080×2400 竖屏 | `[772,133][1036,287]` | — | 与已验证值**逐字节相同** |
| 2400×1080 横屏 | `[1894,133][2158,287]` | 2202 | 与横屏修复**一致** |

**我的建议被纠正**：我提的"板下移到 BottomEnd"是错的——板**本来**就锚在 sheet 上方的 BottomEnd，
唯一剩下的方向是"钻到 sheet 里"，那比丢标签更糟。**"丢标签"才是诚实的兜底**，720 的帧展示了它。

**行为变更要记录（防止以后被"修回去"）**：窄屏下工具入口变成**纯图标**。这是正确的取舍
（能点的图标 > 点不到的标签），但它是一个行为变化，不是单纯的挤压。

**R1/R5 · 窄布局 —— 工具入口丢标签，而不是被裁切。**
当 `rowAvail < 140 + 8 + 96 + 8 + 64 dp`，或 FAB 板的顶边会够到 chrome 行（`bandDp < plateDp + chromeRowDp`）时，
chrome 行预留板宽，工具胶囊变成 56 dp 的纯图标态，让出的宽度给搜索栏。
**这是既定行为，不是挤压的副产品**——能点的图标胜过一个点不到的标签。
在 720×1280 验证（`fab.tools [324,133][478,287]` vs 板起点 `522`），
且 1080×2400 与 2400×1080 的 bounds 与之前验证值逐字节相同。

（实现处两段注释就是给"想把它改回带标签"的人看的：`MapScreen.kt:497` 与 `MapChrome.kt:224`。）

## 32. 窄屏搜索栏：从"一个孤零零的省略号"到"只有图标"（2026-11-02 22:14）

在 720×1280 录制 R7 的验证帧时发现：搜索栏提示词被压缩到一个**孤立的 `…`**——
比不显示更糟，因为它看起来像输入框坏了，而不是"地方不够"。

**修法**：占位提示在可用宽度 < 120 dp 时**不渲染**，只留放大镜图标承担可发现性；
1080×2400 下提示词完全不变。

**两态验证**：`_sheet720-search.png`（只有图标，无省略号）与 `_check1080-placeholder.png`（`搜索地点、坐标或地址` 完整）。

**这是 R7 的延伸**：R7 说"空间不足时让信息让位、绝不让控件重叠"，这里补上第三档——
**信息让位要"整块让"，不能退化成无意义的碎片**。截断到 `搜索…` 尚可接受（仍有语义），
截断到 `…` 则应整块隐藏。

**过程记录**：中途我用 `grep -c 搜索` 判定"提示词消失了"，得到 0 而误以为改坏了——
截图证明它在。**uiautomator 的 dump 与截图不是同一瞬间**，判断"某元素是否可见"时两者都要看，
不要只信其中一个。

## 33. 状态标签改为"整档让位"（2026-11-02 22:28）

720×1280 下**规划器头部**读到 `未开始 · 步…`——又是一个碎片（"步行"只剩一个字）。
两处状态行（peek 卡片 `PeekStatusText`、规划器头部 `Panels.kt`）现在都按**整档**降级：

| 可用宽度 | 显示 |
|---|---|
| ≥ 96 dp | `· 步行 1.4 m/s`（完整） |
| ≥ 40 dp | `· 步行`（只留首词） |
| 更窄 | 不显示模式段 |

**验证**：720 规划器头部 = `未开始 · 步行`（`_planner720-fixed4.png`）；1080×2400 dump 里仍含完整 `步行 1.4 m/s`。

**过程教训**：我第一次改完在 720 看到**没有变化**，因为改的是 peek 卡片那处，而规划器头部是**另一处**同样模式的代码
（`Panels.kt:1042`）。**同一视觉现象可能来自多处代码**——修完必须回到**出问题的那个屏幕**再验一次，
而不是在最近的调用点改完就走。这条与"帧里其他元素也在给你线索"同类：现象的位置 ≠ 代码的位置。

## 34. 状态面板把格式串直接印给了用户（2026-11-02 22:38）

在 720 下走查设置/状态面时撞见：状态面板里有一格标题是 **`≈ %1$.1f km/h`**——用户看到的是原始格式串。
原因：`StatusSheet.kt:125` 用 `stringResource(R.string.label_kmh)` 取一个**带占位符的格式串**当"标题"用，而没传参数。

**修法**：标题改为普通文案 `时速`，数值行自己带 `x.x km/h`（本来就带）。没有第二处使用 `label_kmh`，改动面最小。

**验证**：打开状态面板后 dump 整棵树，`%1` 不再出现，`时速` 存在。

**顺带**：`SheetSupporting` 增加 `maxLines` 参数（默认仍是 2）。摇杆引导弹的正文原本在第 2 行被截成
`…适合在导航、运动类应用…`——半句话，属于 R7 的碎片；该弹窗改为 5 行上限。

**这类缺陷的特征**：它不来自布局或逻辑，而来自**把"格式串"当"文案"用**——`stringResource` 不校验占位符，
编译器也不会报。以后新增带 `%1$` 的字符串时，必须同时检查取用处有没有传参。

## 35. 把"格式串当文案用"变成静态检查（2026-11-02 22:45）

§34 那个缺陷（状态面板印出 `%1$.1f km/h`）不会被编译器、lint 或任何布局检查发现——它只在有人打开那个面板时出现。
所以把它做成检查：`e2e/check_strings.ps1`，并已接入 `e2e/lint.ps1`。

**规则**：`strings.xml` 里所有含 `%N$` 的字符串 ∩ Kotlin 里所有**不带第二个参数**的 `stringResource(R.string.x)` → 失败，
并打印文件、行号、资源名与原始值。

**双向验证**
- `-SelfTest`：用当初真正出货的那个形状（`label_kmh` = 格式串、被无参读取）验证检测器会触发，用修好后的形状验证不误报；
- **真实植入**：把 `label_kmh` 临时改回 `时速 %1$d`，lint 立刻红：
  ```
  [string] StatusSheet.kt:125 reads R.string.label_kmh with no argument, but it is a format string: 时速 %1$d
  lint FAILED: 1 error(s)
  ```
  还原后恢复绿。当前 41 个格式串全部带参使用。

**为什么值得做成检查而不是记住**：这是"**只会在人类打开某个面板时暴露**"的一类缺陷，回归时没有任何自动化会红。
一条 50 行的脚本把它变成每次 lint 都会跑的门禁。
